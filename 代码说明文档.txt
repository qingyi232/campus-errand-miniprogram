    校园跑腿小程序 — 代码说明文档
========================================

一、项目概述
========================================

项目名称：校园跑腿小程序
技术栈：微信小程序（WXML/WXSS/JS）+ Node.js/Express + MySQL
角色划分：用户端（小程序）、商家端（小程序）、管理员端（Web浏览器）

功能模块：
  1. 跑腿服务（取快递、寄快递、帮买服务）
  2. 二手市场（发布/浏览/留言/联系卖家）
  3. 商家入驻（商品管理、订单管理、数据统计、评价管理）
  4. 钱包系统（余额充值、交易记录）
  5. 地图定位（快递点/配送地址选择）
  6. 评价系统（任务完成后互评、商家评分）
  7. 管理后台（用户/商家/任务/订单/轮播/公告/分类/设置管理）

三、数据库设计
========================================

数据库名：campus_errand
字符集：utf8mb4
共 14 张数据表：

1. users — 用户表
   字段：id, openid, phone, password, nickname, avatar, campus,
         dormitory, role(user/merchant/admin), balance,
         credit_score, status, created_at, updated_at
   说明：所有角色共用一张表，通过 role 字段区分

2. merchants — 商家表
   字段：id, user_id(关联users), shop_name, category, contact,
         qualification, announcement, business_hours,
         delivery_range, rating, status(pending/approved/rejected/disabled)
   说明：商家入驻申请后由管理员审核通过才能经营

3. merchant_products — 商家商品表
   字段：id, merchant_id, name, description, price, stock,
         category, images(JSON数组), sales, status(1上架/0下架)
   说明：images 字段存储 JSON 格式的图片URL数组

4. tasks — 跑腿任务表（核心业务表）
   字段：id, user_id(发布者), runner_id(接单者),
         type(express_pickup/express_send/help_buy),
         status(pending/accepted/delivering/completed/cancelled),
         reward, express_point, pickup_code, sender_address,
         receiver_name, receiver_phone, receiver_address,
         goods_desc, buy_location, budget, delivery_address,
         remark, created_at
   说明：支持三种任务类型，状态流转见第八节

5. second_hand_goods — 二手商品表
   字段：id, user_id, title, description, price, original_price,
         category, images(JSON数组), contact,
         status(on_sale/off_shelf/sold), view_count, created_at
   说明：用户发布的二手商品，通过留言联系卖家线下交易

6. goods_comments — 二手商品留言表
   字段：id, goods_id, user_id, content, created_at
   说明：二手商品详情页的留言互动功能

7. reviews — 评价表
   字段：id, task_id, reviewer_id, reviewee_id, merchant_id,
         rating(1-5), content, created_at
   说明：任务完成后发布者和跑腿员可互评

8. orders — 订单表
   字段：id, task_id, merchant_id, user_id, product_id,
         product_name, quantity, total_amount,
         status(pending/preparing/ready/completed/cancelled),
         created_at, updated_at
   说明：商家商品订单和跑腿任务关联订单

9. addresses — 地址表
   字段：id, user_id, name, phone, campus, building, room,
         is_default, latitude, longitude
   说明：用户收货地址管理，支持经纬度定位

10. wallet_records — 钱包记录表
    字段：id, user_id, type(recharge/reward/payment/refund),
          amount, balance_after, description, related_id
    说明：所有资金变动记录（充值、奖励、支付、退款）

11. messages — 消息表
    字段：id, user_id, type(task/order/review/system),
          title, content, related_id, is_read, created_at
    说明：站内消息通知系统

12. banners — 轮播图表
    字段：id, title, image_url, link, sort_order, status
    说明：首页轮播图，管理员可增删改查

13. announcements — 公告表
    字段：id, title, content, status, created_at
    说明：平台公告，首页滚动显示

14. categories — 分类表
    字段：id, name, icon, type(task/market/merchant),
          sort_order, status
    说明：任务/市场/商家的分类管理

五、前端核心代码说明
========================================

5.1 utils/api.js — API 封装层
    封装了统一的 request() 函数，自动处理：
    - 请求地址拼接（BASE_URL + path）
    - JWT Token 自动附加到请求头
    - 统一错误处理和 401 自动跳转登录
    所有页面通过 const api = require('../../utils/api') 调用

5.2 utils/config.js — 配置文件
    定义 BASE_URL（后端地址）、DEFAULT_IMG（默认图片）等常量
    修改后端地址只需改这一个文件

5.3 utils/util.js — 工具函数
    getTaskStatusName()  — 任务状态中文名映射
    getTaskTypeName()    — 任务类型中文名映射
    getTaskStatusColor() — 任务状态颜色映射

5.4 app.js — 小程序入口
    onLaunch 时检查本地存储的登录态（token + userInfo）
    globalData 存储全局用户信息

5.5 页面统一开发模式
    每个页面由 4 个文件组成：
    - xxx.wxml  — 页面结构（类似HTML）
    - xxx.wxss  — 页面样式（类似CSS）
    - xxx.js    — 页面逻辑（数据加载、事件处理）
    - xxx.json  — 页面配置（导航栏标题等）

    生命周期模式：
    onLoad()  → 调用 loadXxx() 加载初始数据
    onShow()  → 部分页面在此刷新数据（如从编辑页返回）
    onPullDownRefresh() → 下拉刷新
    onReachBottom()     → 触底加载更多（分页列表）

七、认证与安全机制
========================================

1. JWT Token 认证
   - 登录成功后服务端签发 JWT Token（有效期7天）
   - 前端存储在 wx.setStorageSync('token')
   - 每次请求自动附加到 Authorization 请求头
   - 后端 authMiddleware 验证 Token 有效性
   - Token 过期或无效返回 401，前端自动跳转登录页

2. 管理员权限控制
   - adminMiddleware 检查 user.role === 'admin'
   - 非管理员访问 /api/admin/* 返回 403

3. 数据权限
   - 用户只能操作自己的数据（任务/商品/地址/钱包）
   - 商家只能管理自己店铺的商品和订单
   - 管理员可操作所有数据


八、关键业务流程
========================================

8.1 跑腿任务流程
    用户A发布任务 → 任务出现在大厅（pending）
    → 用户B接单（accepted）→ 用户B开始配送（delivering）
    → 用户A确认完成（completed）→ 奖励转入用户B钱包
    → 双方可互评
    任何阶段可取消（cancelled）

8.2 任务状态流转
    pending（待接单）→ accepted（已接单）→ delivering（配送中）
    → completed（已完成）
    可随时 → cancelled（已取消）

8.3 二手商品流程
    用户发布商品 → 商品出现在市场（on_sale）
    → 其他用户浏览/留言 → 线下联系交易
    → 卖家手动下架（off_shelf）或标记已售（sold）

8.4 商家入驻流程
    用户提交入驻申请（pending）→ 管理员审核
    → 通过（approved）：用户角色变为merchant，可管理商品
    → 拒绝（rejected）：可重新申请

8.5 商家订单流程
    用户下单 → 商家确认（confirmed）→ 配送中（delivering）
    → 已完成（completed）
    可取消（cancelled）
